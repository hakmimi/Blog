בחלק הזה משתמשים ב-400 תפוחים מומצאים ולא בנתוני הבנק, כי בנתונים מומצאים אנחנו יודעים את האמת ורואים כל נקודה. לכל תפוח שתי מדידות (אדמומיות הקליפה וחומציות המיץ) ותווית אחת: **1 הוא תפוח ירוק, 0 הוא תפוח אדום**. הנתונים סינתטיים, ואין כאן שום טענה על פירות אמיתיים.

## הקו שמחזיר ‎-0.51‎ ו-1.49

**מימוש.** התפוחים באים מהסקריפט `export_apple_grid.py` (עם גרעין קבוע, ולכן הם זהים בכל הרצה). מתאימים רגרסיית ריבועים פחותים רגילה לתוויות ובודקים מה היא חוזה לתפוחים שעליהם אימנו.

```python
import json
import numpy as np

d = json.load(open("../../artifacts/apple_grid.json"))
X = np.column_stack([d["train"]["x"], d["train"]["y"]])      # redness, acidity
y = np.array(d["train"]["label"])
A = np.column_stack([np.ones(len(X)), X])                  # add the intercept column

beta = np.linalg.lstsq(A, y, rcond=None)[0]
line = A @ beta
print(f"{len(y)} training apples, {y.mean():.0%} green")
print(f"line predicts from {line.min():.2f} to {line.max():.2f}")
print(f"below 0: {(line < 0).sum()} apples, above 1: {(line > 1).sum()} apples")
```

**תוצאה.**

```output
400 training apples, 44% green
line predicts from -0.51 to 1.49
below 0: 54 apples, above 1: 38 apples
```

**מה זה אומר.** שום דבר לא מונע מקו לצאת מהטווח 0 עד 1, וכאן זה קורה לעשרות תפוחים. אפשר לחתוך את הערכים, אבל הבעיה עמוקה יותר מהטווח. ארבעה דברים משתבשים כשמתייחסים לתווית 0/1 כאל מספר רגיל:

- **המטרה היא הסתברות.** ממוצע תוויות 0/1 בנקודת מדידה נתונה הוא ה*סיכוי* לירוק שם, ולכן הוא חייב להישאר בין 0 ל-1. קו אינו עושה זאת.
- **הפיזור אינו קבוע.** לתוצאה של כן/לא עם סיכוי `p`, השונות היא `p(1-p)`. היא הגדולה ביותר ב-`p = 0.5` (0.25) ומצטמצמת לכיוון הקצוות (0.09 ב-`p = 0.1`). ריבועים פחותים מניחים אותו פיזור בכל מקום.
- **הטעויות אינן בצורת פעמון.** בכל מדידה תפוח הוא 0 או 1, ולכן הטעות היא אחד משני ערכים, אף פעם לא ענן חלק סביב הקו.
- **הקשר אינו קו.** סיכויים עולים לאט, אחר כך מהר, ואז שוב לאט: צורת S, לא רמפה.

## התיקון: קו בלוג-סיכויים, מכופף בסיגמואיד

**מימוש.** שומרים על קו ישר אבל נותנים לו לחיות בסקאלה אחרת. במקום למדל את ההסתברות `p`, מדלים את ה*לוג-סיכויים* (log-odds) שלה, `log(p / (1 - p))`, שיכול להיות כל מספר. ואז ממירים בחזרה בעזרת ה**סיגמואיד**, `σ(z) = 1 / (1 + e^-z)`, שהופך כל מספר לערך שנמצא בהחלט בין 0 ל-1.

בסמלים, עם שתי מדידות $x_1$ (אדמומיות) ו-$x_2$ (חומציות):

$$z = b + w_1 x_1 + w_2 x_2, \qquad p = \sigma(z) = \frac{1}{1 + e^{-z}}, \qquad \log\frac{p}{1-p} = z .$$

קראו את שלושת אלה יחד. הראשון הוא הקו הישר, שיכול להיות כל מספר ממשי. השני הופך את המספר להסתברות. השלישי אומר את אותו דבר מהכיוון ההפוך: הקו הוא ה*לוג-סיכויים*. פתרון $p = \sigma(z)$ עבור $z$ מחזיר את $\log\frac{p}{1-p}$, ולכן הסיגמואיד והלוג-סיכויים הם פונקציות הופכיות. לשיפוע יש צורה מסודרת,

$$\frac{d\sigma}{dz} = \sigma(z)\bigl(1-\sigma(z)\bigr) \le \tfrac14 ,$$

שהיא הגדולה ביותר ב-$z = 0$ ומצטמצמת לשני הקצוות. צעד של $+1$ ב-$x_j$ מוסיף $w_j$ ללוג-הסיכויים, ולכן הוא מכפיל את הסיכויים $\frac{p}{1-p}$ ב-$e^{w_j}$. המספר הזה הוא **יחס הסיכויים** (odds ratio).

```python
z = np.array([-4, -2, -1, 0, 1, 2, 4])
sigma = 1 / (1 + np.exp(-z))
print("z      ", z)
print("sigma  ", sigma.round(3))
print("slope  ", (sigma * (1 - sigma)).round(3))
```

**תוצאה.**

```output
z       [-4 -2 -1  0  1  2  4]
sigma   [0.018 0.119 0.269 0.5   0.731 0.881 0.982]
slope   [0.018 0.105 0.197 0.25  0.197 0.105 0.018]
```

**מה זה אומר.** שלוש תכונות כדאי לשמור. ב-`z = 0` ההסתברות היא בדיוק 0.5, ולכן ה*גבול ההחלטה ב-0.5* הוא אוסף הנקודות שבהן הקו שווה לאפס. השיפוע הוא `σ(1 - σ)`, לכל היותר 0.25, וכמעט שטוח עבור `z` גדול מאוד או קטן מאוד: ראיות נוספות חשובות ביותר ליד האמצע. ולוג-סיכויים יש קריאה פשוטה. הסתברות 0.8 היא סיכויים של 4 ל-1; מקדם `w` אומר ש*כל יחידה נוספת של המדידה מכפילה את הסיכויים ב-`e^w`*, ובגלל זה הסדרה מדברת בהמשך על **יחסי סיכויים**.

**נסו בעצמכם.** הזיזו את המחוונים וצפו במספר אחד שעובר דרך שתי התמונות. משמאל, הקו הישר $z = b + w x$ ממשיך לגדול. מימין, אותו $z$ עובר דרך הסיגמואיד, ולכן ההסתברות מחליקה בין 0 ל-1 ונשטחת בשני הקצוות. לחצו על **סרוק x** כדי להזיז את הראיה מ-‎-6 עד ‎+6 ולראות את ההסתברות עוברת מ"כמעט בוודאות 0" ל"כמעט בוודאות 1". הקו המקווקו הוא המשיק: השיפוע שלו הוא כמה מהר ההסתברות מגיבה באותה נקודה.

**על מה להסתכל.** שיפוע $w$ גדול יותר מחדד את ה-S (המעבר קורה בטווח צר יותר של $x$); שינוי ההזזה $b$ מחליק את ה-S ימינה או שמאלה בלי לשנות את צורתו; היפוך הסימן הופך את "יותר ראיות פירושו יותר סביר" ל"יותר ראיות פירושו פחות סביר". הנקודה הזהובה מסמנת איפה $p = 0.5$, כלומר את גבול ההחלטה.

**מימוש.** כדי להתאים את המקדמים ממקסמים את הנראות (likelihood) של התוויות, שאין לה פתרון בצורה סגורה. שיטת ניוטון-רפסון פותרת אותה בכמה צעדים עם NumPy בלבד: מחשבים את ה-`p` החזוי, בונים את מטריצת העקמומיות, ועושים צעד.

בסמלים, לוג-הנראות למקסום וצעד ניוטון אחד הם

$$\ell(w) = \sum_i \bigl[\,y_i \log p_i + (1-y_i)\log(1-p_i)\,\bigr], \qquad w \leftarrow w + \bigl(X^{\top} S X\bigr)^{-1} X^{\top}(y - p),$$

כאשר $X$ מכילה עמודה של אחדים ואת המדידות, $p_i = \sigma(x_i^{\top} w)$, ו-$S$ היא המטריצה האלכסונית עם הערכים $p_i(1-p_i)$. שתי שורות ה-NumPy למטה הן בדיוק הנוסחה הזו.

```python
w = np.zeros(A.shape[1])
for step in range(25):
    p = 1 / (1 + np.exp(-A @ w))
    H = A.T @ (A * (p * (1 - p))[:, None])              # curvature of the log-likelihood
    w = w + np.linalg.solve(H, A.T @ (y - p))           # Newton step

from sklearn.linear_model import LogisticRegression
lib = LogisticRegression(C=np.inf, solver="newton-cholesky").fit(X, y)
print("by hand  ", w.round(3))
print("library  ", np.r_[lib.intercept_, lib.coef_[0]].round(3))
print("largest difference", np.abs(w - np.r_[lib.intercept_, lib.coef_[0]]).max().round(8))
print("odds multiplier for +0.1 redness / +0.1 acidity:", np.exp(0.1 * w[1:]).round(2))
```

**תוצאה.**

```output
by hand   [  4.668 -18.777   8.64 ]
library   [  4.668 -18.777   8.64 ]
largest difference 0.00010868
odds multiplier for +0.1 redness / +0.1 acidity: [0.15 2.37]
```

**מה זה אומר.** הלולאה שנכתבה ביד והספרייה מסכימות עד בערך ארבע ספרות אחרי הנקודה. עור אדום יותר מוריד את הסיכויים לירוק (צעד של +0.1 מכפיל אותם בערך ב-0.15), חומציות גבוהה יותר מעלה אותם (בערך פי 2.4). אלה קשרים מותנים בנתונים מומצאים, לא חוקים על תפוחים. חלק 4 עושה את ההתאמה הזו שוב עבור נתוני הבנק ומראה מה קורה כשעוצרים את הלולאה מוקדם מדי.

## מאיפה הסיגמואיד בא

תווית של תפוח היא הטלת מטבע (משתנה *ברנולי*) שהסיכוי שלה תלוי במדידות. דרך מסודרת לראות את הסיגמואיד היא ציון חבוי: לכל תפוח יש "ירקרקות" חבויה (latent), השווה לחלק של קו ישר ועוד רעש אקראי, והוא ירוק כשהציון הזה חוצה את האפס. אם הרעש מתפלג *לוגיסטית*, הסיכוי לחצות הוא בדיוק הסיגמואיד. אם הרעש בצורת פעמון (נורמלי), התוצאה היא מודל ה-*probit*, ושתי העקומות קרובות.

```python
from scipy.stats import norm

zz = np.linspace(-6, 6, 1201)
gap = np.abs(1 / (1 + np.exp(-zz)) - norm.cdf(zz / 1.702)).max()
print(f"largest difference between the logistic curve and a rescaled normal CDF: {gap:.4f}")
```

**תוצאה.**

```output
largest difference between the logistic curve and a rescaled normal CDF: 0.0095
```

**מה זה אומר.** אחרי שינוי סקאלה, שתי עקומות ה-S אף פעם לא נבדלות ביותר מבערך נקודת אחוז אחת. לכן הבחירה ביניהן רק לעיתים נדירות מכריעה בניתוח; ההרגל להשתמש בסיגמואיד בא מנוחות (קריאה נקייה של יחס סיכויים ומתמטיקה פשוטה), לא מהטבע.

## הדרך האחרת לשרטט גבול: לחתוך את המישור לתאים

קו הוא הנחה חזקה: גבול אחד, ישר. הרעיון ההפוך הוא לא להניח כלום על הצורה. חותכים את המישור לרשת של תאים שווים, סופרים תפוחי אימון ירוקים ואדומים בכל תא, ונותנים לכל תא להצביע. זה מה שעצים עושים בדרך אדפטיבית יותר (חלק 6).

**נסו בעצמכם.** הווידג'ט למטה רץ על אותם 400 תפוחי אימון ועל קבוצה נפרדת של 400 תפוחי מבחן. הזיזו את מספר החיתוכים בכל ציר, סמנו את התיבה כדי לראות את תפוחי המבחן, והשוו בין הרשת לבין הקו הלוגיסטי.

**מה זה אומר.** תא אחד (בלי חיתוכים) הוא סתם הצבעת רוב, צודקת בערך ב-56%. רשת גסה של ארבעה תאים כבר מגיעה לבערך 87% על תפוחי המבחן. ככל שהתאים מתכווצים, דיוק האימון מטפס (עד 0.91) ודיוק המבחן לא מתקדם לשום מקום ומתנודד. שלושה דברים משתנים כשהרשת נעשית עדינה יותר: יש פחות תפוחים בתא, ולכן כל הצבעה נשענת על פחות תפוחים; יותר תאים ריקים, ולכן לרשת אין מה לומר שם; וציון האימון יכול רק להשתפר, כי רשת עדינה יותר תמיד יכולה לשנן עוד קצת. זה **המתח בין הטיה לשונות** (bias and variance) שאפשר לראות: רשת גסה נוקשה מדי (הטיה), עדינה רודפת אחרי המקרה (שונות).

**אזהרה לגבי הגדלים.** עם 400 תפוחי מבחן, לדיוק אחד יש שגיאת תקן של בערך 1.7 נקודות, ולכן התנודה בין גדלי רשת שכנים היא רעש. הקריאה הישרה היא המגמה: דיוק האימון עולה, דיוק המבחן לא, והפער נפתח. הקו הלוגיסטי, עם שלושה מספרים, שווה לרשתות הטובות ביותר. זה לא ניצחון כללי של קווים. התפוחים האלה נוצרו עם גבול ישר, ולכן קו אמור להצליח כאן.

## ניתוח ומסקנה

מודל לינארי על תווית 0/1 יכול לחזות "הסתברויות" מחוץ ל-0 עד 1, מניח פיזור קבוע שלא יכול להתקיים, ויש לו צורה לא נכונה. קו בלוג-סיכויים, מכופף בסיגמואיד, מתקן את הטווח ואת הצורה, יש לו קריאה נקייה דרך יחסי סיכויים, ואפשר להתאים אותו ביד עם ניוטון-רפסון. רשת לא דורשת שום הנחה על הצורה, אבל המחיר הוא נתונים: תאים קטנים מדי ריקים או רועשים, וציון האימון אז מחמיא למודל.

המתח הזה, *מודל נוקשה שאולי מחמיץ מבנה מול מודל גמיש שאולי רודף אחרי רעש*, עובר לאורך כל הסדרה. הוא חוזר בחלק 5 (קו הבסיס הלינארי), בחלק 6 (עצים שגדלים עד שהם משננים), בחלקים 7 ו-8 (ממוצע ו-boosting כשתי דרכים לאלף את הגמישות הזו), ובחלק 10 (איך בוחרים הגדרות בלי לרמות את עצמנו). המשיכו ל[חלק 1](/he/series/classification/01-classification-is-a-decision/), שבו אנחנו פוגשים את הנתונים האמיתיים ואת הכללים שכל השוואה נשענת עליהם.
